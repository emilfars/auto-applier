# antislop audit 001 (2026-10-12)

antislop active: during (session override). Source: the M8 kickoff prompt and `plan-revamp.md` section 4.

Scope: the web app on `revamp/m8` after R2 (`web/src`), and the extension's in-page review summary (`extension/src/content.ts`, `apply.ts`). This audit is the input to the R4 rebuild, not a list waiting for approval (`plan-revamp.md` R3). Priority follows the rule tier: Hard Gate = HIGH, Purpose-Gate = MEDIUM, Quality Locks = LOW.

Evidence sources: the R0 screenshot matrix (`scripts/ui-matrix.mjs`), Lighthouse on the production build (performance 70, accessibility 90), `contrast-check.py` from the antislop-human skill, and the component source.

## Findings

| # | Rule | Priority | Where | Finding |
|---|---|---|---|---|
| 1 | R-37 | HIGH | repo | No `DESIGN.md`. The UI was built without written direction. |
| 2 | R-34, R-20 | HIGH | `mantine-theme.ts`, `styles.css` | The brand palette is not applied. The resolver emits the `--mantine-*` overrides on `:root`; Mantine's own `:root[data-mantine-color-scheme="dark"]` rule is more specific and wins, so the page renders Mantine's grey (`--mantine-color-dark-7`) instead of navy `--brand-bg`. AC-WEB-6 passes because it only inspects the map object. Evidence: every baseline screenshot; `web/dist` CSS sets `--mantine-color-body: var(--mantine-color-dark-7)`. |
| 3 | R-25 | HIGH | filled buttons, links, light theme | White on `--brand-primary` (#2E7CF6) is 3.94:1 and the buttons use 12 to 14px text. `--brand-primary` as text on `--brand-surface` is 3.90:1. In the light theme the semantic colors fail as text on white: success 1.92:1, warning 1.67:1, danger 2.77:1. Lighthouse reports `color-contrast`. |
| 4 | R-25 (non-text) | HIGH | inputs, cards | `--brand-border` against `--brand-surface` is 1.49:1 (dark) and #CBD5E1 on white is 1.48:1 (light); input boundaries need 3:1. |
| 5 | R-02 | HIGH | `locales/en.json`, `locales/id.json` | Seven strings per locale contain an em dash. |
| 6 | R-27 | HIGH | `CvPanel`, `EnhancementsPanel`, `JobFeed` | `CvPanel` and `EnhancementsPanel` have no loading state. Saved filters and snippets have no empty state. Load errors show the generic sign-in error string and no next action. The feed error has no retry. |
| 7 | R-03 | HIGH | all screens at 360px | Tap targets under 44px: `size="xs"` buttons (30px) on every job card and CV row, `compact-xs` remove buttons (22px), the theme toggle (34px), the 96px language select. The mobile menu is a bare burger with no label. On a phone the ten filter controls stack above the results, so the first job card sits about two screens down. |
| 8 | R-26, C-2 | HIGH | `JobFeed`, `App` | The filter form's submit button ("Cari") changes nothing: filters already apply on every keystroke. The safety `Alert` renders an empty body. Lighthouse reports a button without an accessible name. |
| 9 | R-27, R-38 | HIGH | `ProfilePanel` | Education and work history are edited as raw JSON in a `JsonInput`. A seeker cannot be expected to write JSON; the control is an implementation detail shown as UI. |
| 10 | R-36 (copy) | HIGH | several | Hardcoded English in an Indonesian-first product: "Invalid email", "Min 8 characters", "Consent required", "Required", "Invalid JSON", "PDF or DOCX", the tracker statuses, and raw enum values such as `part_time`, `form_filled`, `full time`. |
| 11 | R-05, C-3 | MEDIUM | `App.tsx` | The page order is account, CV, profile, tools, then the feed. The feed is the product (PRD G3, G4) and a signed-in user has to scroll past a 21-field form to reach it. The sidebar-plus-stack shell was chosen before asking what each screen is for. |
| 12 | R-06, R-09 | MEDIUM | `JobFeed`, `mantine-theme.ts` | An uppercase "Auto Applier" eyebrow with 0.18em tracking sits above the feed heading and repeats the header title. The theme names Inter but never loads it, so the typeface is whatever the system falls back to, with no written reason. |
| 13 | R-12 | MEDIUM | every `Paper` and `Card` | `shadow="sm"` on every surface. Nothing is elevated relative to anything else. |
| 14 | R-29 | MEDIUM | components | Components use Mantine's own `teal`, `yellow`, `red`, `blue` scales (`c="teal"`, `color="yellow"`) next to the brand tokens, so success green is Mantine teal in one place and `--brand-success` in another. More than three hues outside the token system. |
| 15 | R-04 | MEDIUM | `JobCard`, `CvPanel`, `App` | The magic wand icon marks "Open & Fill" and "Parse". It is the generic "magic" glyph; autofill is not magic and the product's promise is that the user stays in control. |
| 16 | R-09 | MEDIUM | `JobCard` | Up to five badges per card (source in uppercase, employment type, seniority, years, remote) with no hierarchy between them and the pay line. |
| 17 | R-19 | MEDIUM | `styles.css` | `scroll-behavior: smooth` with no `prefers-reduced-motion` guard. |
| 18 | R-11 | LOW | components | `radius="lg"` on cards, `radius="xl"` pills on the theme toggle, `radius="md"` elsewhere, with no stated system. |
| 19 | R-20, Liveliness | LOW | all | No focal point per screen, no identity motif. Swap the title and this is any Mantine starter. |
| 20 | R-27 | HIGH | extension `content.ts` | The in-page review summary is one English sentence in a fixed inline-styled box: no per-state legend, not dismissible, not localized, hardcoded colors. |

## Passing as-is (kept)

- R-21: dark is the default for a written brand reason (`design/brand/palette.md`: "Dark is the default theme (matches brand site)") and a working light toggle exists.
- R-17, R-18, R-36: no statistics, testimonials or trust claims anywhere.
- R-24: every nav item points at a section that exists.
- R-14: job cards are identical on purpose. They are rows of one entity type in a list the user scans and compares (PRD FEED-1), not feature cards.
- Prime Directive copy ("you click Apply yourself") is real product behavior, not a claim.
